# 下单操作

NexusQuant 通过已连接的交易所代为执行订单。以下说明各种订单类型与策略动作的运作方式。

## 订单类型

### 市价单

以最优价格立即执行，大多数策略动作默认使用市价单。

- **优点**：执行快速、保证成交
- **缺点**：在低流动性市场可能产生滑点

### 限价单

以指定价格挂单，仅当市场到达你的价格时才成交。

- **优点**：精确的进出场价格、无滑点
- **缺点**：市场未到达价格则不会成交

::: tip
在 Webhook 信号中，设置 `"order_type": "limit"` 并加入 `"price"` 字段即可使用限价单。
:::

## 各策略的下单行为

### Webhook 信号动作

| 动作 | 行为 |
|------|------|
| `buy` | 开多仓（现货买入或合约做多） |
| `sell` | 开空仓或卖出现有持仓 |
| `long` | 开合约多仓 |
| `short` | 开合约空仓 |
| `close` | 平仓指定交易对的所有仓位 |
| `close_long` | 仅平多仓 |
| `close_short` | 仅平空仓 |

### 止损与止盈

当 Webhook 策略启用 SL/TP 时：
- **止损（Stop Loss）** — 自动挂出条件单限制亏损。当价格跌到止损位时触发市价卖出。
- **止盈（Take Profit）** — 在目标获利价位挂出限价卖单。

SL 和 TP 订单都使用 `reduceOnly` 确保只会平仓，不会反向开仓。

在创建或编辑 Webhook 策略时设置 SL/TP 百分比：
- **止损 %** — 例如 3.0 表示价格从入场价下跌 3% 时平仓
- **止盈 %** — 例如 5.0 表示价格从入场价上涨 5% 时平仓

### 智能定投下单

DCA 订单固定为 BTC/USDT 的**市价买入**。系统包含滑点保护：
- 执行前检查挂单簿深度
- 流动性不足时拆分大额订单
- 滑点超过设定阈值时取消订单

## 订单冲突防护

NexusQuant 在执行新信号前会检查冲突持仓：
- 已有同交易对的多仓时，`buy` 信号不会执行
- 已有同交易对的空仓时，`sell` 信号不会执行

这可防止 TradingView 重复警报造成的意外重复入场。

## 频率限制

为防止信号连发，系统对 webhook 端点设有频率限制。如收到频率限制错误，请等待数秒后重试。
