# 下單操作

NexusQuant 透過已連接的交易所代為執行訂單。以下說明各種訂單類型與策略動作的運作方式。

## 訂單類型

### 市價單

以最佳可用價格立即執行，大多數策略動作預設使用市價單。

- **優點**：執行快速、保證成交
- **缺點**：在低流動性市場可能產生滑價

### 限價單

以指定價格掛單，僅當市場到達你的價格時才成交。

- **優點**：精確的進出場價格、無滑價
- **缺點**：市場未到達價格則不會成交

::: tip
在 Webhook 訊號中，設定 `"order_type": "limit"` 並加入 `"price"` 欄位即可使用限價單。
:::

## 各策略的下單行為

### Webhook 訊號動作

| 動作 | 行為 |
|------|------|
| `buy` | 開多倉（現貨買入或合約做多） |
| `sell` | 開空倉或賣出現有��倉 |
| `long` | 開合約多倉 |
| `short` | 開合約空倉 |
| `close` | 平倉指定交易對的所有部位 |
| `close_long` | 僅平多倉 |
| `close_short` | 僅平空倉 |

### 止損與止盈

當 Webhook 策略啟用 SL/TP 時：
- **止損（Stop Loss）** — 自動掛出條件單限制虧損。當價格跌到止損位時觸發市價賣出。
- **止盈（Take Profit）** — 在目標獲利價位掛出限價賣單。

SL 和 TP 訂單都使用 `reduceOnly` 確保只會平倉，不會反向開倉。

在建立或編輯 Webhook 策略時設定 SL/TP 百分比：
- **止損 %** — 例如 3.0 表示價格從進場價下跌 3% 時平倉
- **止盈 %** — 例如 5.0 表示價格從進場價上漲 5% 時平倉

### 智能定投下單

DCA 訂單固定為 BTC/USDT 的**市價買入**。


## 訂單衝突防護

NexusQuant 在執行新訊號前會檢查衝突持倉：
- 已有同交易對的多倉時，`buy` 訊號不會執行
- 已有同交易對的空倉時，`sell` 訊號不會執行

這可防止 TradingView 重複警報造成的意外重複進場。

## 頻率限制

為防止訊號連發，系統對 webhook 端點設有頻率限制。如收到頻率限制錯誤，請等待數秒後重試。
